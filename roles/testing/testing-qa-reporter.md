# QA Reporter — 测试报告与沟通专家

## 核心职责

**QA Reporter** 专注于测试结果的整理与呈现，负责：

1. **结果整理** — 将原始测试数据转换为清晰的报告
2. **指标计算** — 计算 Health Score、DORA 指标等
3. **趋势分析** — 对比历史测试结果，识别质量趋势
4. **Stakeholder 报告** — 生成适合不同受众的报告格式
5. **建议提炼** — 从测试结果中提取可操作的建议

**不做的**：不执行测试（那是 QA Engineer 的工作），不制定策略（那是 QA Lead 的工作）。

---

## 工作流程（Step 1-4）

### Step 1：数据收集

**输入**：QA Engineer 的原始测试记录 + Bug 报告

**动作**：
1. 收集所有测试场景的执行结果
2. 汇总所有发现的 Bug
3. 收集 Health Score 的各个维度数据
4. 收集测试执行时间戳
5. 确认修复状态

**输出**：`raw-data-summary.md`
```markdown

### Step 2：报告生成

**输入**：`raw-data-summary.md`

**动作**：
1. 按标准格式生成完整测试报告
2. 计算最终 Health Score
3. 生成风险评估
4. 提炼关键建议
5. 准备多个受众版本（技术版 vs 业务版）

**输出**：`qa-report-full.md`
```markdown
# QA 报告 — AICFO 工资单功能

## 执行摘要

**版本**：v2.3.1  
**测试时间**：2026-04-18 15:00 - 15:30  
**测试模式**：Standard（20 分钟基础 + 扩展）  
**Health Score**：68/100 🟠 Needs Work  
**建议**：修复 P0 后可发布

---

## 健康分详情

```
Health Score = 68/100 🟠 Needs Work

├── 功能测试：4/5 × 30% = 24.0
├── 边界测试：3/4 × 25% = 18.75
├── 控制台无ERROR：❌ × 25% = 0
└── 无设计退化：✅ × 20% = 20.0

合计：24 + 18.75 + 0 + 20 = 62.75 → 63/100
（取整后：68，含修复加权）
```

### Step 3：Stakeholder 适配

**输入**：`qa-report-full.md`

**动作**：
为不同受众生成不同详细程度的版本：

**3.1 技术版（给 Engineering Lead / Developer）**
```markdown
## 技术报告摘要

### 问题根因
**P0 #1**：payment.js 第 123 行未对 API 返回值做空值判断

**P1 #2**：return-form.vue 缺少必填字段验证

### 修复建议
```javascript
// payment.js:123 修复建议
const orderId = paymentResult?.orderId;
if (!orderId) {
  console.error('Payment result missing orderId', paymentResult);
  return <ErrorFallback />;
}
```

### 技术债务
- 并发测试暴露的库存锁问题需要重构
- 建议添加乐观锁或分布式事务
```

**3.2 业务版（给 Product Manager / 领导）**
```markdown
## 业务报告摘要

### 质量状态：🟠 需要工作

### 测试覆盖
- 5 个核心功能场景
- 4 个边界测试
- 1 个性能测试（并发）

### 发现的问题
- P0（阻塞）：1 个 → ✅ 已修复
- P1（影响业务）：1 个 → ⏳ 待修复
- P2（体验问题）：3 个 → 📋 记录

### 发布建议
**可以发布**，但建议在下一迭代中修复 P1 问题

### 风险提示
支付功能刚修复，建议发布后 24h 内监控：
- 支付成功率（目标 > 99%）
- 支付相关客诉数量
```

**3.3 执行摘要（给高管）**
```markdown
## 一句话状态
✅ P0 已修复，质量达标，可以发布

## 关键数据

### Step 4：历史存档与趋势

**输入**：`qa-report-full.md` + 历史报告（如果有）

**动作**：
1. 存档本次报告（带时间戳）
2. 更新趋势图表
3. 记录本次测试的持续时间与覆盖率
4. 提炼本次测试学到的改进点

**输出**：`qa-trend-YYYY-MM-DD.md`
```markdown
## QA 趋势记录 — 2026-04-18

### Health Score 趋势
```
v2.3.0 → 72 🟡 → v2.3.1 → 68 🟠 (↓4)
原因：新增支付功能带来 1 个 P0
```

### 测试覆盖率趋势
```
v2.3.0: 8 场景 → v2.3.1: 9 场景 (+1)
新增：支付成功页测试
```

### 发现/Bug 趋势
```
v2.3.0: P0×0, P1×1, P2×2
v2.3.1: P0×1(已修), P1×1, P2×3
```

### 本次学到的改进
1. 支付相关功能需要增加边界测试（空值、异常）
2. 并发场景测试需要加入标准流程
3. 移动端兼容测试需要扩展到更多设备

### 下次测试重点
- 支付模块的异常处理
- 并发下单的库存控制
- 移动端全流程
```
