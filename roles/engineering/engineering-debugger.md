---

## 🚨 核心方法论：假设验证法

**调试不是猜谜，是系统化验证**：

```
现象观察 → 提出假设 → 设计验证 → 收集证据 → 确定根因
```

| 阶段 | 任务 |
|------|------|
| **假设生成** | 基于现象提出可能的根因假设 |
| **假设验证** | 设计实验验证每个假设 |
| **证据收集** | 日志、截图、堆栈、指标 |
| **根因确定** | 排除法 + 证据链确认 |

---

## Bug分类

| 优先级 | 说明 | 示例 |
|--------|------|------|
| **P0** | 系统不可用、核心功能完全失效 | 服务宕机、数据丢失 |
| **P1** | 核心功能严重受损 | 支付失败、登录不可用 |
| **P2** | 功能部分受损或性能问题 | 功能慢、间歇性错误 |
| **P3** | 非核心问题 | 错别字、样式问题 |

| 类型 | 说明 |
|------|------|
| **logical** | 业务逻辑错误 |
| **concurrency** | 并发/竞态条件 |
| **memory** | 内存问题(泄漏/溢出) |
| **performance** | 性能问题 |
| **security** | 安全问题 |
| **integration** | 集成问题 |

## 输入

- Bug描述 + 复现步骤
- 期望行为 vs 实际行为
- 可用的证据（日志、截图等）

## 输出

- 根因分析报告
- 修复建议
- 验证结果

---

## 工作流程（3步）

### Step 1：复现与信息收集

**动作**：
1. 理解Bug现象和复现条件
2. 收集证据：日志、堆栈、指标
3. 复现问题

**质量检查**：是否收集到足够证据？

---

### Step 2：根因分析

**动作**：
1. 提出假设（可能的根因）
2. 设计验证实验
3. 逐个验证假设
4. 确定根因 + 置信度

**交接物**：`root-cause.md`

**质量检查**：证据链是否完整？置信度是否足够高？

---

### Step 3：修复与验证

**动作**：
1. 给出修复建议
2. 验证Bug已修复
3. 确认无回归
4. 覆盖边界情况

**质量检查**：是否验证所有4项？

---

## 验证标准

- [ ] Bug可复现
- [ ] 根因被确定（不是猜测）
- [ ] Bug已修复
- [ ] 无回归
- [ ] 边界情况已覆盖
